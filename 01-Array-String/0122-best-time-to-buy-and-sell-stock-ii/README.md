# 122. Best Time to Buy and Sell Stock II

- **난이도**: Medium
- **유형**: 그리디, 배열
- **링크**: https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/
- **최초 풀이**: 2026-08-27 / **결과**: 통과 (피드백 0회)

---

## 문제 요약

`prices[i]` = `i`번째 날의 주가. 매일 사거나 팔 수 있지만 **한 번에 한 주만 보유**. (같은 날 팔고 다시 사는 것 허용)
**최대 이익**을 반환.

```
[7,1,5,3,6,4] → 7      1에 사서 5에 팔고(+4), 3에 사서 6에 팔고(+3)
[1,2,3,4,5]   → 4
[7,6,4,3,1]   → 0      계속 내려감 → 거래 안 함
```

```
1 <= prices.length <= 3 * 10^4
0 <= prices[i] <= 10^4
```

---

## 내 풀이 (통과)

```ts
function maxProfit(prices: number[]): number {
    let totalProfit = 0
    let buyPrice = Infinity

    for (const price of prices) {
        if (price < buyPrice) {
            buyPrice = price
        } else if (price > buyPrice) {
            totalProfit += price - buyPrice
            buyPrice = price
        }
    }

    return totalProfit
}
```

- **시간 `O(n)` / 공간 `O(1)`** — 스스로 정확히 제시
- 검증: 고정 10건 · **완전탐색 대조 4천건** · **DP 대조 20만건** 전부 불일치 0건. 최대 입력 3만 × 1000회 49ms

멘탈 모델: *"저가에 사두고, 오르면 팔고 **그 자리에서 즉시 재매수**한다."*

---

## ⚠️ 핵심 지적 — 논증이 **주장**에서 멈췄다

> 내가 쓴 이유: *"무제한으로 거래할 수 있다는건 반드시 이득이 날때마다 그 합을 다 더한게 무조건 최대 이득이라는걸 **알기 때문에**"*

**결론은 맞지만 "안다"는 근거가 아니다.**

그리디는 *"매 순간 최선 = 전체 최선"* 이라는 **위험한 가정**을 깐다. 이 가정은 대부분의 문제에서 **틀린다.**
바로 [0121. Best Time to Buy and Sell Stock](../0121-best-time-to-buy-and-sell-stock/README.md) 에서도 "이득 날 때마다 판다"는 `7`을 내놓지만 **정답은 `5`** 다(거래 1회 제한).

→ 면접에서 이 문제는 **반드시** *"왜 그게 최대인지 증명해 보세요"* 가 따라온다.

---

## 증명 — 망원경 논법 (telescoping)

### 1단계: 모든 거래는 **하루짜리 거래들의 합**으로 쪼개진다

`i`일 매수 → `j`일 매도의 이익:

```
p[j] − p[i]
  = (p[i+1]−p[i]) + (p[i+2]−p[i+1]) + … + (p[j]−p[j−1])
```

중간 항이 **서로 지워진다**(망원경처럼 접힘). `[7,1,5,3,6,4]` 에서 `1`에 사서 `6`에 판 이익 `5`:

```
(5−1) + (3−5) + (6−3)  =  4 + (−2) + 3  =  5   ✅
```

> **어떤 기간의 거래든 그 사이 하루짜리 차이의 총합과 같다** — 손해 구간(`−2`)까지 억지로 껴안은 채로.

### 2단계: 그러므로 **양수만 고른 합이 상한**

어떤 거래 조합을 짜든 결국 **하루짜리 차이의 부분집합**을 고르는 것. 합이 최대가 되려면 **음수를 하나도 안 고르면** 된다.

```
[7,1,5,3,6,4] 의 하루짜리 차이:  −6, +4, −2, +3, −2
양수만:                            +4      +3        = 7   ← 넘을 수 없는 천장
```

### 3단계: 그 상한이 **달성 가능**하다

천장을 알아도 **닿을 수 없으면 무의미**하다. 여기선 닿는다 — 양수 차이가 나는 날마다 *"전날 사서 오늘 판다"*.
같은 날 팔고 재매수가 허용되고 한 주만 들면 되므로 **제약 위반 없음**.

```
1에 사서 5에 팔고 → 즉시 3에 사서 6에 팔고  →  4 + 3 = 7  ✅
```

> ### 🔑 그리디 증명의 표준 형태 ②
> **① 어떤 답도 넘을 수 없는 상한을 만든다 → ② 내 알고리즘이 그 상한에 닿는다 → ③ 그러므로 최적**
>
> [0121. Best Time to Buy and Sell Stock](../0121-best-time-to-buy-and-sell-stock/README.md) 의 **교환 논증**과 함께 그리디 증명의 두 축. → [그리디 알고리즘](../../concepts/greedy.md)

## ⚠️ `buyPrice` 는 사실 **직전 가격**이다

두 분기를 나란히 보면:

```ts
if (price < buyPrice)      { buyPrice = price }                     // buyPrice ← price
else if (price > buyPrice) { totalProfit += …; buyPrice = price }   // buyPrice ← price
// 같을 때는 아무것도 안 함 → 이미 buyPrice === price
```

**모든 경로에서 `buyPrice` 가 `price` 가 된다.** 즉 매 반복이 끝날 때 항상:

```
buyPrice === 직전에 본 가격
```

→ *"연속 차이 합"* 코드와 **20만건 전부 일치**함을 확인. **두 코드는 같은 코드다.**

### 정리된 버전

```ts
function maxProfit(prices: number[]): number {
    let total = 0
    for (let i = 1; i < prices.length; i++) {
        if (prices[i] > prices[i - 1]) total += prices[i] - prices[i - 1]
    }
    return total
}
```

`buyPrice`, `Infinity`, 세 갈래 분기가 전부 사라진다. **속도는 동일**(둘 다 `O(n)`).
얻는 것은 **논증이 코드에 드러난다**는 것 — *"양수 차이를 전부 더한다"* 는 증명을 그대로 읽을 수 있다.

> 변수명 `buyPrice` 는 *"매수 가격을 들고 있다"* 고 말하지만 실제로는 아무것도 사고 있지 않다.
> `#변수명불명확` 계열이나, "저가 매수 → 오르면 매도 → 즉시 재매수" 멘탈 모델과는 일치하므로 **카운트 미포함**.

## 알아야 할 상식

### `Infinity` 초기값

```ts
let buyPrice = Infinity     // 최솟값을 찾을 때
let maxVal   = -Infinity    // 최댓값을 찾을 때
```

`prices[0]` 로 초기화하고 `i=1`부터 도는 것과 동등하다. `Infinity` 쪽은 **빈 배열도 자연히 처리**되는 게 장점(여기선 `length >= 1` 보장이라 무관).

⚠️ `let min = 0` 으로 초기화하는 실수 주의 — 음수가 들어오면 깨진다. **`0`은 "아직 없음"이 아니라 "값이 0"이다.**

### 이 문제의 DP 해법 (참고)

그리디가 안 보일 때의 안전한 대안. `#309`(쿨다운), `#714`(수수료), `#123`(2회 제한) 은 **그리디가 깨지고 DP만 통한다.**

```ts
let hold = -Infinity   // 주식 보유 중일 때의 최대 이익
let free = 0           // 미보유일 때의 최대 이익
for (const p of prices) {
    const prevHold = hold
    hold = Math.max(hold, free - p)      // 계속 보유 vs 오늘 매수
    free = Math.max(free, prevHold + p)  // 계속 미보유 vs 오늘 매도
}
return free
```

`O(n)` / `O(1)` 로 동일하지만 **제약이 추가돼도 확장된다.** 이 문제에선 그리디가 더 짧다.
