# 121. Best Time to Buy and Sell Stock

- **난이도**: Easy
- **유형**: 배열, **그리디**, 한 번 순회
- **링크**: https://leetcode.com/problems/best-time-to-buy-and-sell-stock/
- **최초 풀이**: 2026-08-03 / **결과**: 브루트포스(TLE) → 그리디로 통과

---

## 문제 요약

`prices[i]` = `i`일의 주가. **딱 한 번 사고 그 뒤에 한 번 팔아** 얻는 최대 이익. 못 벌면 `0`.
- **Constraints**: `1 <= prices.length <= 10⁵`, **`0 <= prices[i] <= 10⁴`** ← 가격 0 가능!

---

## 1차 시도 — 브루트포스 (시간 초과)

```ts
for (let i = 0; i < prices.length; i++) {
    for (let j = i+1; j < prices.length; j++) {
        if (prices[j] - prices[i] > max) max = prices[j] - prices[i]
    }
}
```

### 이중 반복문 세는 법

`j = i+1` 부터 시작하는 형태는 **"모든 쌍을 한 번씩"** 이다.

| i | j 횟수 |
|---|---|
| 0 | `n-1` |
| 1 | `n-2` |
| … | … |
| n-2 | `1` |

```
합 = (n-1) + (n-2) + ... + 1 = n(n-1)/2 = (n² - n)/2
→ 상수 버림, 최고차항만  →  O(n²)
```

**`n = 10⁵` → 50억 번 → TLE**

> 안쪽 루프가 평균 `n/2`번만 돌아도 `O(n²)`이다. 상수 배는 Big-O를 못 바꾼다.
> `n(n-1)/2` 패턴은 앞으로 계속 나온다. 보이면 즉시 `O(n²)`로 판단.

---

## 관점 전환 — 되돌아가지 않기

| | 관점 | 결과 |
|---|---|---|
| 브루트포스 | **사는 날**을 고정 → 미래를 전부 스캔 | 매번 되돌아감 → `O(n²)` |
| ❌ 시도했던 오답 | **파는 날**을 고정 → 과거를 전부 스캔 | 여전히 되돌아감 → `O(n²)` |
| ✅ 정답 | 지나가는 **모든 날이 차례로 파는 날 후보** | 한 번 순회 → `O(n)` |

핵심:
> `i`번째 날에 도착했을 때 `0 ~ i-1`일은 **이미 지나오면서 봤다.**
> 그중 최저가를 **변수에 들고 있으면** 다시 스캔할 이유가 없다.

```
오늘의 이익 = 오늘 가격 − (오늘 이전의 최저가)
```

### 트레이스: `[7, 1, 5, 3, 6, 4]`

| 날 | 가격 | 오늘 팔면? | 최대이익 | 최저가 |
|---|---|---|---|---|
| 0 | 7 | — | 0 | **7** |
| 1 | 1 | `1−7 = -6` 무시 | 0 | **1** ← 갱신 |
| 2 | 5 | `5−1 = 4` | **4** | 1 |
| 3 | 3 | `3−1 = 2` | 4 | 1 |
| 4 | 6 | `6−1 = 5` | **5** | 1 |
| 5 | 4 | `4−1 = 3` | 5 | 1 |

**되돌아간 적이 한 번도 없다.**

## 최종 정답

```ts
function maxProfit(prices: number[]): number {
    let max = 0
    let low = Infinity

    for (let i = 0; i < prices.length; i++) {
        if (prices[i] < low) {
            low = prices[i]
        }
        if (prices[i] - low > max) {
            max = prices[i] - low
        }
    }
    return max
}
```

- **시간 `O(n)` / 공간 `O(1)`**
- 이 문제의 **이론적 하한**. 정렬 안 된 배열이라 모든 원소를 최소 한 번은 봐야 하므로 `O(n)`보다 빠를 수 없다.

---

## ⚠️ 1차 오답 — 센티널 값 안티패턴

```ts
let low = 0
if (low === 0 || prices[i] < low) { low = prices[i] }   // ❌
```

`0`을 **"아직 설정 안 됨"** 표식으로 사용. 그런데 Constraints상 **`0`은 유효한 실제 가격**이다.

### 반례: `prices = [0, 5]` → `0` 반환 (정답 `5`)

| i | prices[i] | `low === 0` | low | 결과 |
|---|---|---|---|---|
| 0 | 0 | ✅ | `low = 0` | max=0 |
| 1 | 5 | **✅ (여전히 0!)** | **`low = 5`** ← 버그 | max=0 |

> ### 🔑 센티널 값은 "실제 데이터에 절대 나올 수 없는 값"이어야 한다.
> `0`, `-1`을 표식으로 쓰기 전에 **"이 값이 진짜 데이터로 들어올 수 있나?"** 를 반드시 확인.
> 실무에서도 자주 터지는 버그 (`id = 0`, `count = -1` 등).

### 관용구

```ts
let min = Infinity      // 최솟값 찾기
let max = -Infinity     // 최댓값 찾기
```
어떤 실제 숫자도 `Infinity`일 수 없으므로 센티널 충돌이 원천 차단된다.

## 알아야 할 상식

### 1. 복잡도 순서 — `O(n log n) 이하`는 상한선이다

```
O(1)  <  O(log n)  <  O(n)  <  O(n log n)  <  O(n²)
빠름 ←                                       → 느림
```

"`n ≤ 10⁵` → `O(n log n)` 이하"는 **"그보다 느리면 안 된다"** 는 뜻.
`O(n)`은 그 상한선을 **넉넉히 만족**한다. `O(n log n)`을 목표로 만들라는 게 아니다.

### 2. `O(log n)`이 불가능한 이유

`O(log n)` = **대부분의 원소를 안 보고 건너뛴다** (`n = 10⁵` 이면 17번만 봄).
이 배열은 **정렬되어 있지 않으므로** 안 본 원소가 최저가/최고가일 수 있다 → 하나도 못 건너뛴다.

> 이진 탐색이 `O(log n)`인 건 **"정렬되어 있다"** 는 정보 덕에 절반을 버릴 수 있어서다.
> **정보가 없으면 건너뛸 수 없다.**

### 3. 왜 그리디인가 → [그리디 알고리즘](../../concepts/greedy.md)

**그리디 선택**: "지금까지 본 것 중 최저가"를 유지하고, 예전 최저가는 버린다.

**왜 버려도 안전한가 (지배 논증)**: 새 최저가 `p_new < p_old` 라면, **미래 어떤 날 `d`에 팔더라도**
```
price[d] − p_new  >  price[d] − p_old
```
**항상** 새 것이 이긴다 → `p_old`는 어떤 시나리오에서도 다시 쓸 일이 없다.

### 4. 중복 조건

```ts
if (prices[i] - low > 0 && prices[i] - low > max)   // 앞 조건 불필요
```
`max`는 `0`에서 시작해 절대 음수가 안 되므로, `> max`가 참이면 `> 0`도 자동으로 참.

### 5. `Math.max` / `Math.min` 로 간결하게

```ts
for (const price of prices) {
  low = Math.min(low, price);
  max = Math.max(max, price - low);
}
```
`low`를 먼저 갱신해도 되는 이유: 오늘 사서 오늘 팔면 이익 `0`이라 `max`에 영향 없음.

---

## 실수 노트

- **브루트포스를 짜기 전에 Constraints를 안 봤다** → `n = 10⁵`를 봤다면 `O(n²)`는 후보에서 즉시 제외됐어야 함. **문제 읽는 순서: 제목 → Constraints → 본문**
- `0`을 센티널로 사용 → `Infinity` 관용구로
- 복잡도 상한선(`O(n log n) 이하`)을 목표치로 오해

### 2026-08-12 (1회차) — 통과, 접근 피드백 1회

백지 재작성 **통과**. node 고정 12건 + 랜덤 20만건(가격 `0` 포함) 불일치 0. 최대 입력 200회 20ms.
복잡도 `O(n)` / `O(1)` 정확.

```ts
function maxProfit(prices: number[]): number {
    let profit = 0
    let min = Infinity // 구매하는날의 최솟값

    for (const price of prices) {
        if (price < min) {
            min = price
        }
        if (profit < price - min) {
            profit = price - min
        }
    }

    return profit
}
```

> *"파는 날짜를 고정해두고 … 구매일을 +1 … 조건에 반하면 판매일을 바꾸고 다시 판단"*

| | 관점 | 결과 |
|---|---|---|
| 브루트포스 | 사는 날 고정 → 미래 전부 스캔 | `O(n²)` |
| **❌ 08-03에 이미 오답으로 기록** | **파는 날 고정 → 과거 전부 스캔** | 여전히 `O(n²)` |
| ✅ 정답 | 지나가는 모든 날이 차례로 파는 날 후보 | `O(n)` |

다만 **복잡도를 지적하자 바로 알아채고 스스로 "j 이전의 최솟값만 알면 된다"까지 도달**했다. 태그는 안 올림.

#### 🔑 진짜 막힌 지점 — "i와 j 둘 다 있는 거야?"

**구매일 포인터가 사라진다**는 게 이 문제의 핵심인데 거기서 한 번 걸렸다.

```
브루트포스   i (사는 날) + j (파는 날)   → 포인터 2개 → O(n²)
정답         j (오늘) 하나 + 변수 min    → 포인터 1개 → O(n)
```

**"몇 번째 날에 샀는지"는 답에 필요 없다.** 필요한 건 **"그때까지 본 가장 싼 가격"이라는 숫자 하나**뿐이라, 인덱스가 아니라 **변수**에 담긴다.

> ### 🔑 되돌아가야 할 것 같으면, 그 정보를 **변수 하나로 압축**할 수 있는지 먼저 본다
> 압축되면 포인터가 하나 사라지고 `O(n²)` → `O(n)`.
> → 같은 발상이 [0392. Is Subsequence](../../03-Two-Pointers/0392-is-subsequence/README.md) Follow-up(전처리 인덱싱), [2996. Smallest Missing Integer Greater Than Sequential Prefix Sum](../../02-Hashmap/2996-smallest-missing-integer-greater-than-sequential-prefix-sum/README.md)(재스캔 → Set)에도 나온다.

#### 구현 시 확인한 것 — 루프 시작점

```
(a) j = 0 부터, min 초기값 = Infinity   ← 채택
(b) j = 1 부터, min 초기값 = prices[0]
```
(a)는 **최저가 갱신을 먼저** 해야 안전하다. `j=0`에서 이익 계산을 먼저 하면 `prices[0] - Infinity = -Infinity`.
"오늘 사서 오늘 판다"는 이익이 `0`이라 답에 영향이 없으므로 갱신을 먼저 해도 문제없다.

### 2026-08-27 (2회차) — 통과, **피드백 0회** · `3일` → `7일` 단계

고정 14건 + 랜덤 30만건(가격 `0` 포함) 불일치 0. 최대 입력(10⁵) 200회 25ms.

```ts
function maxProfit(prices: number[]): number {
  let profit = 0
  let minBuyPrice = Infinity

  for (const price of prices) {
    if (price < minBuyPrice) {
        minBuyPrice = price
    }

    if (profit < price - minBuyPrice) {
        profit = price - minBuyPrice
    }
  }

  return profit
}
```
