# 그리디 알고리즘 (Greedy)

> **매 순간 지금 당장 가장 좋아 보이는 선택을 하고, 절대 되돌아보지 않는다.**
> 그 선택들의 합이 전체 최적해가 되는 문제에서만 쓸 수 있다.

---

## 1. 정의

그리디는 **"전략"이 아니라 "성질"** 이다. 아무 문제에나 쓸 수 있는 게 아니라, 그리디가 **성립하는 문제**에서만 통한다.

```
1. 현재 시점에서 가장 좋은 선택을 한다     (지역 최적)
2. 그 선택을 확정하고 되돌아보지 않는다    (되돌리기 없음)
3. 반복한다
```

핵심은 **2번**이다. 되돌아보지 않기 때문에 한 번의 순회로 끝나고, 그래서 보통 `O(n)` 또는 `O(n log n)`이 나온다.

---

## 2. 성립 조건 두 가지

### ① 탐욕적 선택 속성 (Greedy Choice Property)
**지금의 지역 최적 선택이 전역 최적해의 일부가 된다.**
= 그리디로 고른 선택 때문에 최적해를 놓치는 일이 없다.

### ② 최적 부분 구조 (Optimal Substructure)
**전체 최적해가 부분 문제의 최적해를 포함한다.**

> ②만 있고 ①이 없으면 → **DP를 써야 한다.**
> ①이 있으면 → 그리디가 DP보다 훨씬 빠르고 간단하다.

---

## 3. 성립하는 예 — [0121. Best Time to Buy and Sell Stock](../01-Array-String/0121-best-time-to-buy-and-sell-stock/README.md)

**그리디 선택**: "지금까지 본 것 중 가장 싼 값"을 사는 시점으로 유지한다.

```
[7, 1, 5, 3, 6, 4]
 ↓
day0: 최저가 7
day1: 1이 더 싸다 → 최저가 1  ← 7은 여기서 영원히 버려짐
day2~5: 1보다 싼 게 안 나옴 → 계속 1
```

### 왜 7을 버려도 안전한가 — 지배(dominance) 논증

새 최저가 `p_new < p_old` 라 하자. **미래의 어떤 날 `d`에 팔더라도**:

```
price[d] − p_new   >   price[d] − p_old
```

**항상** 새 최저가가 이득이다. 예외 상황이 하나도 없다.
→ `p_old`는 **어떤 시나리오에서도 다시 쓸 일이 없다** → 버려도 안전

> 이렇게 **"한 선택이 다른 선택을 모든 경우에서 이긴다"** 는 걸 보이면 그리디가 증명된다.

---

## 4. ⚠️ 실패하는 예 — 동전 거스름돈

**이 예제를 반드시 기억할 것.** 그리디가 왜 위험한지 보여준다.

### 성립하는 경우: 동전 `[1, 5, 10]` 으로 `30`원

```
그리디(큰 것부터): 10 + 10 + 10  →  3개
최적해:            10 + 10 + 10  →  3개  ✅ 일치
```

### 실패하는 경우: 동전 `[1, 4, 5]` 로 `8`원

```
그리디(큰 것부터): 5 + 1 + 1 + 1  →  4개  ❌
최적해:            4 + 4          →  2개
```

**5를 집는 순간 최적해를 놓친다.** "지금 가장 큰 걸 집는다"는 지역 최적이 전역 최적을 망친 것.

> **똑같은 그리디 전략이 동전 구성에 따라 되기도 하고 안 되기도 한다.**
> 그래서 "그리디로 풀어야지"가 아니라 **"이 문제에서 그리디가 성립하나?"** 를 먼저 물어야 한다.

이런 문제는 DP로 풀어야 한다 (→ 322. Coin Change)

### ❗ 흔한 오해: "동전을 무한개 쓸 수 있으면 그리디가 되지 않나?"

**반대다. 위 예시가 이미 무한개 전제다.**

```
최적해 4 + 4 = 2개  ← 4를 두 개 쓴다 = 무한개니까 가능
```

무한개 조건이 그리디를 살리는 게 아니라, **오히려 그리디를 이기는 대안(4+4)을 만들어준다.**
동전을 하나씩만 쓸 수 있었다면 `4+4`는 애초에 불가능했다.

### 진짜 원인은 **액면가 구성**이다

| 동전 구성 | 8원 | 그리디 |
|---|---|---|
| `[1, 4, 5]` | 그리디 `5+1+1+1`=4개 / 최적 `4+4`=2개 | ❌ |
| `[1, 5, 10]` | 그리디=최적=4개 | ✅ |

둘 다 무한개인데 결과가 다르다. **개수가 아니라 값의 구성이 문제.**
`[1,4,5]`는 `5`와 `4`가 너무 가까워서, `5`를 집어 얻는 이득(1)보다 남은 `3`을 1원짜리로 채우는 손해(3개)가 크다.

### 충분조건: 배수 사슬 (chain divisibility)

> **각 동전이 바로 위 동전의 약수이면 그리디가 항상 최적이다.**

**한국 동전** `1, 5, 10, 50, 100, 500`
```
1|5 ✅  5|10 ✅  10|50 ✅  50|100 ✅  100|500 ✅   → 그리디 보장
```
→ 편의점에서 큰 동전부터 거슬러주는 게 **수학적으로 최적해**인 이유.

**`[1, 4, 5]`**: `1|4` ✅ 이지만 **`4 ∤ 5`** ❌ → 사슬이 끊김 → 보장 없음 → 실제로 실패

**단, 필요조건은 아니다.** 미국 동전 `1, 5, 10, 25`는 `10 ∤ 25` 로 사슬이 끊겨도 그리디가 최적이다.

| | 결론 |
|---|---|
| 배수 관계 O | **무조건 됨** (보장) |
| 배수 관계 X | 될 수도, 안 될 수도 (개별 확인 필요) |

임의 동전 구성의 그리디 성립 여부 판별은 그 자체로 어려운 문제 (Pearson's algorithm 필요).
→ **322. Coin Change는 임의 구성을 주므로 무조건 DP.**

### 검증 방법의 교훈

"조건을 바꾸면 항상 참이 되나?"를 묻는 것 **자체는 정확한 검증법**이다.

```
121번:  price[d] − p_new  >  price[d] − p_old     ← 예외 없음 ✅
동전:   8원에서 5를 집으면 4개, 4를 집으면 2개     ← 반례 존재 ❌
```
**반례가 하나라도 있으면 그리디는 죽는다.**

---

## 5. 그리디 vs 완전탐색 vs DP

| | 방식 | 복잡도 | 조건 |
|---|---|---|---|
| **완전탐색** | 모든 경우를 다 시도 | `O(2ⁿ)` 등 | 항상 정답. 대신 느림 |
| **DP** | 부분 문제 결과를 저장해 재사용 | `O(n²)` 등 | 최적 부분 구조 필요 |
| **그리디** | 매 순간 최선만 고르고 직진 | `O(n)`, `O(n log n)` | **+ 탐욕적 선택 속성** 필요 |

**같은 문제를 셋 다로 풀 수 있다면 그리디가 가장 빠르다.** 대신 성립 여부를 확인해야 한다.

---

## 6. 실전 판별법

### 방법 1. 반례 찾기 (코테에서 현실적)
그리디 전략을 정한 뒤 **깨뜨릴 입력을 만들어 보려 시도**한다.
5분 고민해도 반례가 안 나오면 밀고 나간다. 시간이 없으니까.

### 방법 2. 교환 논증 (Exchange Argument, 정석)
> "최적해가 내 그리디 선택과 다르다고 가정하자.
> 최적해의 그 부분을 내 선택으로 **바꿔치기해도 더 나빠지지 않는다**를 보인다."

바꿔치기가 항상 가능하면 그리디 = 최적. [0121. Best Time to Buy and Sell Stock](../01-Array-String/0121-best-time-to-buy-and-sell-stock/README.md) 의 지배 논증이 이 형태.

### 신호 — 그리디를 의심해볼 상황
- "최대/최소를 구하라" + 배열을 한 번 훑으면 될 것 같은 감
- **정렬해놓고 보면 답이 보일 때** (회의실 배정, 구간 스케줄링)
- 미래 정보가 없어도 지금 결정을 내릴 수 있을 때

### 신호 — 그리디가 안 될 것 같은 상황
- 지금의 선택이 **미래의 선택지를 제약**할 때 (동전, 배낭)
- "몇 가지 방법이 있는가" 같은 **개수 세기** 문제 → 보통 DP
- 반례가 쉽게 만들어질 때
