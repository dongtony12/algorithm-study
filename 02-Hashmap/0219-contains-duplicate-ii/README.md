# 219. Contains Duplicate II

- **난이도**: Easy
- **유형**: 배열, **Set + 슬라이딩 윈도우**
- **링크**: https://leetcode.com/problems/contains-duplicate-ii/
- **최초 풀이**: 2026-08-26 / **결과**: 통과 (접근 피드백 3회 — 범위를 윈도우로 좁히는 부분)

---

## 문제 요약

`nums[i] === nums[j]` 이면서 **`|i - j| <= k`** 인 서로 다른 인덱스가 존재하는가.
= **같은 값이 두 번 나오는데 그 두 위치의 거리가 `k` 이하**인 경우가 있는가.

```
[1,2,3,1],     k=3  →  true    (인덱스 0,3 — 거리 3)
[1,0,1,1],     k=1  →  true    (인덱스 2,3 — 거리 1)
[1,2,3,1,2,3], k=2  →  false   (같은 값끼리 전부 거리 3)
```

- **Constraints**: `1 <= nums.length <= 10^5`, `-10^9 <= nums[i] <= 10^9`, **`0 <= k <= 10^5`**
  ← **`k` 도 입력**이므로 복잡도 축이 둘일 수 있다

---

## ⚠️ 브루트포스는 왜 죽나

1차 접근: *"거리 `k` 부터 1까지 줄여가며 각 거리마다 배열 전체를 훑는다"*

```
n = nums.length (≤ 10⁵),  k = 주어진 정수 (≤ 10⁵)

O(n × k) = 10⁵ × 10⁵ = 10¹⁰      →  TLE
```

**스스로 TLE를 판단했다.** `k = 0` 이면 무조건 `false`(서로 다른 인덱스인데 거리가 0일 수 없다)라는 것도 정확히 짚음.

---

## 🔑 핵심 — 범위를 "전체"가 아니라 "윈도우"로

매 `i` 마다 반복하는 질문:

> **"`nums[i]` 와 같은 값이 거리 `k` 이내에 있었나?"**

**"거리 `k` 이내"는 인덱스로 `i-k` 부터 `i` 까지**다. 그 구간만 `Set` 에 들고 다니면 된다.

```
nums = [1, 2, 3, 1],  k = 3

i=3 일 때 볼 구간:  인덱스 0 ~ 3   (원소 k+1 = 4개)
i=4 로 가면:        인덱스 1 ~ 4   ← 0번이 빠지고 4번이 들어온다
```

> ### 🔑 [0001. Two Sum](../0001-two-sum/README.md) 과의 차이는 **"무엇을 기억하고 무엇을 버리는가"**
> | | 기억해야 할 것 | 자료구조 |
> |---|---|---|
> | [0001. Two Sum](../0001-two-sum/README.md) | **지금까지 본 전부** | `Map`(값→인덱스), 계속 쌓임 |
> | **219** | **최근 `k`개만** | `Set` + **오래된 것 삭제** |
>
> 기억할 범위가 유한하면 **버리는 동작**이 생기고, 그게 슬라이딩 윈도우다.

---

## 최종 정답

```ts
function containsNearbyDuplicate(nums: number[], k: number): boolean {
    const numsSet = new Set()

    for (let i = 0; i < nums.length; i++) {
        if (numsSet.has(nums[i])) {
            return true
        }

        numsSet.add(nums[i])

        if (numsSet.size > k) {
            numsSet.delete(nums[i-k])       // 윈도우 밖으로 밀려난 값 제거
        }
    }

    return false
}
```

- **시간 `O(n)` / 공간 `O(k)`** (정확히는 `O(min(n, k))`)
- 검증: 고정 14건 + 랜덤 30만건 불일치 0. 최대 입력(10⁵, k=10⁵) 200회 633ms(1회 3ms)

**왜 되는가**: `Set` 에는 항상 **최근 `k`개만** 남으므로, `has` 가 참이면 그 값은 **반드시 거리 `k` 이내**에 있다.

### Set 크기는 "항상 `k`" 가 아니라 "최대 `k`"

```
nums = [1,2,3,4,5],  k = 2

i=0:  add(1)  →  {1}        size 1      ← 아직 k 미만
i=1:  add(2)  →  {1,2}      size 2
i=2:  add(3)  →  {1,2,3}    size 3 > k  →  delete(nums[0]=1)  →  {2,3}
i=3:  add(4)  →  {2,3,4}    size 3 > k  →  delete(nums[1]=2)  →  {3,4}
```

- `i < k` 구간: 지울 게 없어 `size < k`
- 그 이후: `add` 로 `k+1` 이 됐다가 하나 지워 **정확히 `k` 유지**

**중복이 있으면 `has` 에서 이미 `true` 로 빠져나가므로** Set 안에는 항상 서로 다른 값만 남는다. 그래서 `size` = 윈도우 안 원소 개수가 정확히 맞아떨어진다.

### `k = 0` 이 별도 분기 없이 처리되는 이유

```
add 후 size = 1 > 0  →  delete(nums[i - 0]) = 방금 넣은 것을 바로 지움
→ Set이 항상 비어 있음  →  has 가 절대 참이 안 됨  →  false
```

## 알아야 할 상식

### 1. 삭제 인덱스가 `i - k` 인 이유

`i` 에서 `add` 한 뒤 지우는 것이므로, 남는 건 인덱스 `i-k+1 .. i` 의 `k`개.
다음 반복 `i+1` 에서 `has` 로 확인할 때 그 값들과의 거리는 `1 .. k` — **정확히 조건을 만족하는 범위**다.

### 2. `Map`(값→인덱스)으로도 풀린다

```ts
const last = new Map<number, number>()
for (let i = 0; i < nums.length; i++) {
  if (last.has(nums[i]) && i - last.get(nums[i])! <= k) return true
  last.set(nums[i], i)                  // 항상 최신 인덱스로 갱신
}
return false
```
**공간이 `O(n)`** 이 되지만(삭제를 안 하므로) 코드는 더 직관적이다.
*"가장 최근에 나온 위치만 기억하면 된다"* 는 게 근거 — 더 예전 것은 거리가 멀기만 하다.

### 3. 이 패턴이 `04-Sliding-Window` 주제다

아직 시작 안 한 주제인데 이 문제가 그 입문형이다.
**고정 크기 윈도우**를 유지하며 한 칸씩 밀고, 들어오는 것 넣고 나가는 것 빼는 구조.

## 실수 노트

- **범위를 "전체"로 잡았다** → *"i=0부터 j까지 Set에 넣고 `nums.length` 와 size 비교"*. **전체가 아니라 거리 `k` 구간**만 봐야 한다. 이 지점이 유일하게 힌트를 받은 곳
- ✅ **`k = 0` 처리를 스스로** — 서로 다른 인덱스인데 거리 0은 불가능
- ✅ **브루트포스 `O(n × k)` = 10¹⁰ → TLE 를 스스로 판단**. 축이 둘인 것도 정확
- ✅ **`Set` 으로 중복을 감지한다는 핵심 아이디어를 스스로 도달** (*"set의 size가 다르면"*)
- ✅ 윈도우 크기 `k+1`, `has` 사용, 삭제 인덱스 `i-k` 전부 질문에 즉답
- ✅ 복잡도 `O(n)` / `O(k)` 정확
