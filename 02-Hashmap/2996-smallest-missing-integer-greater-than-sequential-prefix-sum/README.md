# 2996. Smallest Missing Integer Greater Than Sequential Prefix Sum

- **난이도**: Easy
- **유형**: 배열, **Set 조회**, 두 단계 문제
- **링크**: https://leetcode.com/problems/smallest-missing-integer-greater-than-sequential-prefix-sum/
- **최초 풀이**: 2026-08-11 / **결과**: **1차 오답**(검사 범위) → 수정 후 통과. 힌트 0단계 (반례 지적만)
- **출처**: LeetCode Daily 2026-08-11 (목록 밖 보충 문제)

## 문제 요약

**① 가장 긴 sequential prefix의 합**을 구하고, **② 그 합 이상이면서 `nums`에 없는 가장 작은 정수**를 반환.

- sequential prefix: 모든 `1 <= j <= i` 에 대해 `nums[j] === nums[j-1] + 1`. **`nums[0]` 하나만으로도 sequential.**
- **Constraints**: `1 <= nums.length <= 50`, **`1 <= nums[i] <= 50`** ← **모든 원소가 양수**인 게 아래 논증의 핵심

```
[1,2,3,2,5]         prefix [1,2,3] 합 6  →  6 없음        → 6
[3,4,5,1,12,14,13]  prefix [3,4,5] 합 12 →  12,13,14 있음 → 15
```

---

## ⚠️ 1차 오답 — 검사 범위를 잘못 잡음

```ts
for (let j = i; j < nums.length; j++) {    // ❌ i부터 시작
    if (x === nums[j]) { j = i; x++ }
}
```

두 번째 루프를 `j = i` 부터 시작해 **`nums[0..i-1]`(sequential prefix 구간)을 통째로 검사에서 제외**했다.

### 반례

| nums | 기대 | 1차 코드 | 왜 |
|---|---|---|---|
| `[5]` | **6** | 5 | prefix = `[5]`, 합 = 5. 그런데 `nums[0]=5`를 안 봄 |
| `[1,5,2]` | **3** | 1 | prefix = `[1]`, 합 = 1. `nums[0]=1`을 안 봄 |
| `[2,1,3,4,5]` | **6** | 2 | 위와 동일 |

**`i === 1` 일 때 `x = nums[0]` 이므로 `nums[0]` 자신과 반드시 겹친다.** 그런데 `j = i = 1` 부터 봐서 그 칸을 건너뛰었다.

## 최종 정답

```ts
function missingInteger(nums: number[]): number {
    let x = nums[0]
    let i = 1

    while (nums[i] === nums[i - 1] + 1) {
        x += nums[i]
        i++
    }

    for (let j = i - 1; j < nums.length; j++) {   // i-1 부터
        if (x === nums[j]) {
            j = i - 1                              // 되돌려서 재스캔
            x++
        }
    }

    return x
}
```

- **시간 `O(n²)` / 공간 `O(1)`**
- 검증: 고정 12건 + **완전탐색 1,554건**(길이 1~4, 값 1~6) + **랜덤 30만건** 전부 통과

---

## 🔑 `j = i - 1` 이 왜 충분한가 — 근거 있는 코드로 만들기

`j = 0`이 아니라 `i - 1` 부터 봐도 되는 이유. **이걸 설명 못 하면 `#우연히맞는코드` 다.**

```
prefix = [a, a+1, a+2, ..., a+i-1]        최댓값 = a + i - 1
x      = a + (a+1) + ... + (a+i-1)  =  i·a + i(i-1)/2

x − 최댓값 = (i-1)·a + (i-1)(i-2)/2
              ↑ i ≥ 2 이고 a ≥ 1 이므로 항상 양수
```

**가장 작은 경우(`i = 2`)로 확인**:
```
prefix = [a, a+1]  →  x = 2a + 1,  최댓값 = a + 1
2a + 1 > a + 1  ⟺  a > 0        ← Constraints `1 <= nums[i]` 가 보장
```

> ### 원소가 전부 양수면, **2개 이상의 합은 그중 어떤 원소보다도 크다.**
> → `i >= 2` 면 prefix 안의 값은 `x` 이상이 될 수 없다 → 검사할 이유가 없다.
> → `i === 1` 만 예외. 원소가 하나면 **"합 = 그 원소 자신"** 이라 `x`와 정확히 겹친다.
> `j = i - 1` 은 **딱 그 한 칸만 살려두는** 표현이다.

⚠️ **`a >= 1` 조건이 없으면(0이나 음수가 허용되면) 이 논증은 무너진다.** Constraints에 의존하는 최적화이므로, 문제가 바뀌면 함께 무너진다는 걸 알고 써야 한다. → [0088. Merge Sorted Array](../../01-Array-String/0088-merge-sorted-array/README.md) 의 `i >= 0` 가드 논의와 같은 성격

## ⚠️ 복잡도

**1차 답변**: `O(M + n)` — **틀림.** 입력이 `nums` 하나뿐인데 없는 축 `M`을 만들었고, 값도 틀렸다.
**2차 답변**: `O(n²)` — **정확.** 되돌아가는 구조를 스스로 인식함.

```
for (let j = i - 1; ...) {
    if (x === nums[j]) { j = i - 1; x++ }    // ← 되돌림 = 재스캔
}
```

- `x`가 1 오르려면 `x`가 `nums`에 있어야 함 → 증가 횟수 ≤ **서로 다른 값 개수** ≤ `n`
- 증가할 때마다 최대 `n`칸 재스캔
- → **`O(n × n) = O(n²)`**

> 🔑 **`for` 문이 하나여도 인덱스를 되돌리면 `O(n)`이 아니다.**
> "되돌아가는가?" 를 보면 [0121. Best Time to Buy and Sell Stock](../../01-Array-String/0121-best-time-to-buy-and-sell-stock/README.md) 의 브루트포스와 같은 구조.

공간 `O(1)` — 자료구조 생성 없음. 정확.

## 2차 풀이 — Set (시간 `O(n)`) · 08-11 직접 작성

반복되는 질문이 **"이 값이 `nums`에 있나?"** 하나뿐이라는 걸 보면 바로 나온다.

```ts
function missingInteger(nums: number[]): number {
    let x = nums[0]
    let i = 1

    while (nums[i] === nums[i - 1] + 1) {
        x += nums[i]
        i++
    }

    const test = new Set(nums)        // ⚠️ 이름은 seen / numSet 이 맞다

    while (test.has(x)) {
        x++
    }

    return x
}
```

검증: 완전탐색 9,330건(길이 1~5, 값 1~6) + 랜덤 30만건 불일치 0.

| | 시간 | 공간 | "있냐?" 비용 |
|---|---|---|---|
| 재스캔 방식 | `O(n²)` | `O(1)` | `O(n)` × 증가 횟수 |
| **Set** | **`O(n)`** | `O(n)` | **`O(1)`** × 증가 횟수 |

`while` 이 몇 번 도나: `x`가 오르려면 `test`에 있어야 하는데 서로 다른 값은 최대 `n`개 → **최대 `n+1`번** → 전체 `O(n)`.

> ### 🔑 공간 `O(n)`을 내주고 시간 `O(n²) → O(n)` 을 산다
> **해시맵/Set 문제의 본질이 전부 이 거래다.** → [해시맵](../../concepts/hashmap.md)

---

## ⚠️ 실측 — 복잡도가 좋은 쪽이 더 느렸다

```
n = 50, 20만회 반복
재스캔 O(n²) :  16ms
Set     O(n) : 114ms      ← 7배 느림
```

**이유 두 가지**
1. **`n = 50`은 너무 작다.** `O(n²)` = 2,500번 vs `O(n)` = 50번. 절대 횟수 차이가 미미한 구간
2. **`new Set(nums)` 의 상수가 크다.** 해시 계산 + 메모리 할당이 배열 인덱스 읽기보다 훨씬 비싸다. `n=50`에서는 이 고정 비용이 알고리즘 이득을 통째로 잡아먹는다

> ### 🔑 Big-O는 **`n`이 충분히 클 때**의 이야기다
> 두 곡선에는 교차점이 있고, `n`이 작으면 상수가 큰 쪽이 진다.
> 판단 기준은 **"지금 빠른가"가 아니라 "Constraints의 상한에서 살아남는가"**.
> `n = 10⁵` 였다면 재스캔은 죽는다. → [0026. Remove Duplicates from Sorted Array](../../01-Array-String/0026-remove-duplicates-from-sorted-array/README.md) 의 *"LeetCode runtime 수치는 신뢰하지 말 것"* 과 같은 얘기

**면접에서는 Set 버전을 말하되, "다만 n이 50이라 실제로는 재스캔이 더 빠릅니다"까지 덧붙이면 훨씬 좋은 답변.**

## 알아야 할 상식

### 1. `while (nums[i] === nums[i-1] + 1)` 의 범위 이탈

`i`가 `nums.length`에 도달하면 `nums[i]`는 `undefined` → `undefined === 숫자` 는 `false` → 루프 종료. **크래시는 안 난다.**

하지만 [0088. Merge Sorted Array](../../01-Array-String/0088-merge-sorted-array/README.md) 에서 본 것과 같은 **암묵적 의존**이다. 명시적으로:
```ts
while (i < nums.length && nums[i] === nums[i-1] + 1) { ... }
```
Java·C++ 였으면 예외/UB. JS만 관대하다.

### 2. 문제를 두 단계로 쪼개 읽기

이 문제는 사실 **독립된 두 문제**가 붙어 있다.
```
① 가장 긴 sequential prefix의 합    ← 단순 순회
② 합 이상인 최소 missing 정수        ← 조회 문제
```
②만 떼어놓고 보면 **`41. First Missing Positive`** (Hard)의 축소판이다. 붙어 있는 문제는 **접속사에서 끊어 읽으면** 각각이 쉬워진다.

### 3. `Set` 생성 비용

```js
new Set(nums)     // O(n) 시간, O(n) 공간 — 한 번만
set.has(x)        // O(1) 평균
```
**루프 안에서 `new Set(...)` 을 만들면** 그 순간 `O(n²)`이 된다. → [0169. Majority Element](../../01-Array-String/0169-majority-element/README.md) 의 `#숨은반복문` 과 같은 함정.

## 실수 노트

- **두 번째 루프의 시작 인덱스를 `i`로 잡아 prefix 구간을 검사에서 누락** → `[5]`, `[1,5,2]` 오답. **"이 루프가 커버해야 하는 범위가 정확히 어디까지인가"** 를 먼저 정하고 시작할 것 `#인덱스오프바이원`
- **1차 복잡도 `O(M + n)`** — 입력이 하나뿐인데 존재하지 않는 축 `M`을 만들었다. 2차에 `O(n²)`로 스스로 정정
- **`const test = new Set(nums)`** — `test`는 무엇을 담았는지 전혀 알려주지 않는다. `seen` / `numSet` / `exists` 처럼 역할이 드러나야 한다 (`#변수명불명확` 계열이지만 정답 코드의 스타일 이슈라 카운트는 올리지 않음 — 08-12 판단)
- ✅ **`j = i - 1` 이 충분한 이유를 스스로 논증해냄** (`2a+1 > a+1 ⟺ a > 0`, Constraints가 보장) — `#우연히맞는코드` 를 근거 있는 코드로 전환
- ✅ 되돌아가는 구조 = `O(n²)` 를 스스로 인식
- ✅ 공간복잡도 `O(1)` 정확 (4문제 연속)
- ✅ **힌트 없이 Set 최적화를 스스로 구현** — "반복되는 질문이 뭔가"를 짚어주자 바로 도달

### 2026-08-19 (1회차) — 코드는 통과, **접근 단계에서 과거 실수 2개 재발**

최종 코드 **통과**. 고정 12건 + **완전탐색 9,330건**(길이1~5, 값1~6) + 랜덤 30만건 불일치 0.
복잡도 `O(n)` / `O(n)` 정확.

```ts
function missingInteger(nums: number[]): number {
    let x = nums[0]
    let numSet = new Set(nums)

    for (let i = 1; i < nums.length; i++) {
        if (nums[i] === nums[i-1] + 1) {
            x += nums[i]
        } else {
            break
        }
    }

    while (numSet.has(x)) {
        x++
    }

    return x
}
```

**08-11의 최종 개선안(Set 버전)을 백지에서 바로 재현했다.** `break` 로 루프를 끊는 구조도 정확.

#### ⚠️ 재발 ① 검사 범위 — `#인덱스오프바이원` 4회

접근 1차: *"sequential 원소값들은 제외, 제외하지 않은 인덱스부터 순회"*
→ **prefix 구간을 통째로 버리는 것.** 08-11에 `j = i` 로 시작해 틀렸던 것과 **같은 뿌리.**

```
nums = [5]      prefix=[5], x=5
인덱스 0을 제외 → 남은 인덱스 없음 → 5 반환   ❌  정답 6
```

**교정**: *"버리는 기준은 **인덱스가 아니라 값**"* — 스스로 도달함.
`x` 보다 작은 값은 `x` 이상이 될 수 없으니 볼 필요가 없고, `[5]` 의 `5`는 `x=5` 보다 작지 않으니 **검사 대상에 남는다.**

> 🔑 논증 *"prefix 합이 sequential 원소 중에서 나올 수 없다"* 는 **prefix 길이 ≥ 2일 때만** 성립한다.
> **길이 1이면 합 = 그 원소 자신**이라 정확히 겹친다. 이 예외를 잊으면 매번 같은 자리에서 틀린다.

#### ⚠️ 재발 ② 복잡도 — `#복잡도차원뭉개기` 6회

접근 1차: **`O(m+n)`** → 입력이 `nums` **하나뿐인데 축을 둘로** 만들었다. (08-11에도 `O(M+n)` 으로 같은 실수)
2차: **`O(m×n)`** → 여전히 두 축
3차: 빈칸을 채우자 **`O(n²)`** 도달, 그리고 **`Set` 으로 `O(n)`** 까지 스스로 복원

```
크기를 결정하는 입력이 몇 개인가?   →  1개,  n = nums.length
x가 최대 몇 번 오르나?              →  서로 다른 값 ≤ n개  →  최대 n번
한 번 오를 때마다 몇 칸 훑나?        →  재스캔이면 n칸
                                    →  n × n = O(n²)
Set 조회로 바꾸면                    →  O(1) × n번 = O(n)
```

> 08-11 노트에 **본인이 적어둔 문장**: *"`for` 문이 하나여도 인덱스를 되돌리면 `O(n)`이 아니다."*
