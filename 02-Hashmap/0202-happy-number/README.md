# 202. Happy Number

- **난이도**: Easy
- **유형**: 수학, **Set 사이클 감지**, 첫 `log n` 문제
- **링크**: https://leetcode.com/problems/happy-number/
- **최초 풀이**: 2026-08-20 / **결과**: 통과 (접근 피드백 3회 — 자료구조·종료조건·복잡도 / 구현 버그 1회)

---

## 문제 요약

각 자릿수의 **제곱의 합**으로 계속 바꿔서 `1` 이 되면 happy number, 사이클에 빠지면 아니다.

```
19  →  1²+9²=82  →  8²+2²=68  →  6²+8²=100  →  1²+0²+0²=1     true
2   →  4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → ...        false (4로 회귀)
```

- **Constraints**: `1 <= n <= 2^31 - 1`
  ← **입력이 "배열 길이"가 아니라 "숫자 값"** 이다. 지금까지와 성격이 다르다

---

## 접근

```
① Set 하나 준비
② n !== 1 인 동안 반복
     - 이미 Set에 있으면 → false (사이클)
     - Set에 넣고, n = 각 자릿수 제곱합
③ 루프를 빠져나오면(n === 1) → true
```

**왜 되는가**: 사이클이면 반드시 **이전에 본 값**이 다시 나온다. `1` 은 자기 자신으로 고정되므로 `n !== 1` 조건이 그대로 성공 종료가 된다.

### ⚠️ `Map` 이 아니라 `Set`

접근 1차는 *"Map 하나를 선언해두고 … **value는 뭐든지 상관없음**"* 이었다.
**값이 필요 없고 "있었나 없었나"만 묻는다면 `Set`.** → [해시맵](../../concepts/hashmap.md) 의 자료구조 선택 기준

---

## 🔑 복잡도 — 첫 `log n` 문제

접근에서 `O(m+n)` → `O(n)` 순으로 틀렸다. **둘 다 아니다.**

### 값 `n` 과 "자릿수"는 다르다

```
n = 2,147,483,647        ← 값은 21억
자릿수 = 10개            ← 실제로 훑는 건 10번
```

`O(n)` 이면 **21억 번 연산**한다는 뜻이다. 실제로는 몇십 번이면 끝난다.

```
n = 9        자릿수 1
n = 99       자릿수 2      ← 값은 11배인데 자릿수는 +1
n = 999      자릿수 3
n = 9,999    자릿수 4

자릿수 ≈ log₁₀(n) + 1
```

> ### 🔑 **"값이 곱셈으로 커질 때 작업량이 덧셈으로 커진다" — 이게 `log` 다.**

### 왜 상수로 수렴하나 — `810` 상한

```
10자리 수의 각 자릿수 제곱합 최댓값 = 9² × 10 = 810
→ 한 번만 변환하면 값이 무조건 810 이하로 떨어진다
→ 그 뒤로는 1 ~ 810 안에서만 논다
```

| | |
|---|---|
| 첫 변환 | 자릿수만큼 훑기 → `O(log n)` |
| 그 뒤 루프 | 값이 810 이하 → 반복 횟수도, 각 변환도 **상수** |
| Set 크기 | 최대 810개 → **입력이 커져도 안 늘어남** |

**시간 `O(log n)` / 공간 `O(1)`**

> 🔑 **입력이 "숫자 값"이면 작업량은 보통 `log n`(자릿수)이거나 `n`(값만큼 반복)이다.**
> 배열 문제에서 `n` 이 "길이"였던 것과 완전히 다르다. `06-Binary-Search` 주제에서 `log` 가 본격적으로 나온다.

## 최종 정답

```ts
function isHappy(n: number): boolean {
    const nSet = new Set()
    let sum = 0

    while (n !== 1) {
        let numToString = n.toString()
        let stringLength = numToString.length

        for (let i = 0; i < stringLength; i++) {
            sum += (Number(numToString[i]) * Number(numToString[i]))
        }

        if (nSet.has(sum)) {
            return false
        } else {
            nSet.add(sum)
        }

        n = sum
        sum = 0
    }

    return true
}
```

- **시간 `O(log n)` / 공간 `O(1)`**
- 검증: 고정 16건 + **전수 검사 1~200,000** + 랜덤 20만건(1~2³¹-1) 불일치 0. 최대 입력 20만회 43ms

## ⚠️ 구현 버그 — `sum` 을 선언하고 `n` 에 누적했다

```ts
let sum = 0
    ...
    n += (Number(numToString[i]) * Number(numToString[i]))     // ❌ sum 이어야 함
    ...
    if (nSet.has(sum))      // sum 은 계속 0
    n = sum                 // n 이 0 으로 덮어써짐
```

`n = 19` 트레이스:
```
i=0:  n += 1²  →  n = 20
i=1:  n += 9²  →  n = 101        ← 원본 위에 계속 더해진다
sum 은 여전히 0  →  nSet.add(0)  →  n = 0
다음 반복에서 nSet.has(0) 이 걸려 false
```

**happy number 인 것(7, 19, 23, 100 …)이 전부 `false`** 로 나왔다.

> 그때는 `noteMap`/`magazineMap`, 여기는 `n`/`sum`.
> *(다만 복사 실수가 아니라 처음부터 잘못 쓴 것이라 카운트는 올리지 않음 — 08-20 판단)*

**대책**: 누적 변수를 쓸 때 **선언한 이름과 누적하는 이름이 같은지** 한 번 확인. 특히 원본 입력(`n`)과 누적값(`sum`)이 둘 다 숫자면 눈에 안 띈다.

## 개선 — 문자열 변환 없이

```ts
let sum = 0
while (n > 0) {
    const d = n % 10
    sum += d * d
    n = Math.floor(n / 10)
}
```

복잡도는 같지만 **매 반복의 `toString()` 할당이 사라진다.**

## 알아야 할 상식

### 1. Set 없이 `O(1)` 공간 — Floyd's Cycle Detection

**두 포인터를 다른 속도로** 굴리면 Set 없이 사이클을 감지할 수 있다.

```
slow = 한 번 변환,  fast = 두 번 변환
둘이 만나면 → 사이클
fast 가 1 이 되면 → happy
```

`08-Linked-List` 의 `141. Linked List Cycle` 이 **정확히 같은 기법**이다. 거기서 제대로 다룬다.
지금은 *"Set 말고도 방법이 있다"* 정도만.

### 2. 사이클은 왜 반드시 생기나

값이 `1 ~ 810` 이라는 **유한 집합** 안에서만 움직이므로, 811번 안에 반드시 이전 값이 나온다 (비둘기집 원리).
그래서 **무한 루프 걱정 없이** "이전에 봤나"만 확인하면 된다.

### 3. `4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4`

happy 가 아닌 모든 수는 **이 사이클 하나**로 수렴한다. 알려진 사실이라 `Set` 대신 이 8개만 하드코딩해도 통과한다 — 다만 **문제의 의도가 아니고 근거를 설명하기 어렵다.**

## 실수 노트

- **`Map` 을 쓰려 함** → 값이 필요 없으면 `Set`. [해시맵](../../concepts/hashmap.md) 선택 기준
- **`true` 반환 조건(`n === 1`)이 접근에 없었다** → `false` 조건만 서술
- **복잡도 `O(m+n)` → `O(n)`** 둘 다 오답. 입력이 하나뿐인데 축을 둘로 만들었고(`#복잡도차원뭉개기` 계열), 그다음엔 **값 `n`** 과 **자릿수**를 혼동
- **`sum` 을 선언하고 `n` 에 누적** → happy number 가 전부 `false`. [0383. Ransom Note](../0383-ransom-note/README.md) 와 뿌리가 같음 (카운트 미포함)
- ✅ **사이클 감지 아이디어를 스스로 도출** — "같은 수가 다시 나오면 무한히 돈다"
- ✅ 지적 후 `Set` · 종료조건 · `log n` 전부 한 번에 교정
