# 1. Two Sum

- **난이도**: Easy
- **유형**: 배열, **해시맵 (값 → 인덱스)**, 1패스
- **링크**: https://leetcode.com/problems/two-sum/
- **최초 풀이**: 2026-08-18 / **결과**: 통과 (**접근 피드백 3회 전부 사용** — 필터 오류 · 복잡도 · 맵 방향/시점)

---

## 문제 요약

합이 `target` 인 두 수의 **인덱스**를 반환. 정답은 정확히 하나, 같은 원소 두 번 사용 불가, 반환 순서 무관.

```
[2,7,11,15] t=9  →  [0,1]
[3,2,4]     t=6  →  [1,2]
[3,3]       t=6  →  [0,1]      ← 같은 값, 다른 인덱스
```

- **Constraints**: `2 <= nums.length <= 10^4`, **`-10^9 <= nums[i], target <= 10^9`** ← **음수가 들어온다**
- **Follow-up**: `O(n²)` 보다 빠르게?

### [0167. Two Sum II - Input Array Is Sorted](../../03-Two-Pointers/0167-two-sum-ii-input-array-is-sorted/README.md) 와의 차이

| | 167 | **1 (이 문제)** |
|---|---|---|
| 정렬 | 되어 있음 | **안 되어 있음** |
| 인덱스 | 1-indexed | **0-indexed** |
| 공간 제약 | `O(1)` 요구 | **없음** |
| 해법 | 양끝 투 포인터 `O(n)` / `O(1)` | **해시맵** `O(n)` / `O(n)` |

> 🔑 **같은 "Two Sum"인데 주어진 조건이 해법을 결정한다.**
> 167은 *"정렬되어 있다"* 를 써서 공간을 `O(1)`로 유지했고, 여기는 정렬이 없으니 **공간 `O(n)`을 내주고 시간을 산다.** 정확히 반대 거래.

---

## ⚠️ 1차 접근 오류 — "target보다 작은 수만 판별하면 됨"

**틀렸다.** Constraints에 `-10^9 <= nums[i]` — **음수가 들어온다.**

```
nums = [10, -5],  target = 5
        ↑
     10 > 5 이지만 정답의 일부다  (10 + (-5) = 5)
```

`target` 보다 큰 수도 **음수와 짝지으면** 답이 될 수 있다. 필터링 조건이 성립하지 않는다.

> 🔑 **Constraints의 하한(`-10^9`)도 상한만큼 중요하다.** `#Constraints미확인`

---

## ⚠️ 복잡도 — 중첩인데 덧셈으로 셌다

1차 접근(브루트포스)의 복잡도를 **`O(m+n)`** 이라고 답했다. 두 가지가 틀렸다.

### ① 중첩은 곱셈

```
순차 (나란히)  →  더한다   O(m + n)
중첩 (안에)    →  곱한다   O(m × n)
```
→ [0383. Ransom Note](../0383-ransom-note/README.md) 에서 정리한 규칙

### ② 축이 둘인 건 "독립적인 입력이 둘"일 때다

두 루프가 **같은 배열**을 돌면 `m`과 `n`이 같은 값이다.

```
m = nums.length,  n = nums.length      ← 같다
O(m × n) = O(n × n) = O(n²)
```

| 문제 | 입력 | 복잡도 |
|---|---|---|
| [0028. Find the Index of the First Occurrence in a String](../../01-Array-String/0028-find-the-index-of-the-first-occurrence-in-a-string/README.md) | `haystack`, `needle` — **독립 2개** | `O(n × m)` |
| [0383. Ransom Note](../0383-ransom-note/README.md) | `s`, `t` — **독립 2개** | `O(m + n)` |
| **1 (이 문제)** | `nums` — **1개** | **`O(n²)`** |

> 🔑 **입력이 하나면 축도 하나다.** 억지로 `m`, `k` 로 나누지 않는다.
> `#복잡도차원뭉개기` 의 반대 방향 실수 — 없는 축을 만들어냈다.

`n = 10⁴` → `n²` = 10⁸. 통과는 하지만 Follow-up이 요구하는 건 이걸 줄이는 것.

## ⚠️ 2차 접근 오류 — 맵의 방향과 시점

### ① 키/값 방향이 반대였다

```ts
mapNum.set(i, nums[i])      // ❌ 키 = 인덱스, 값 = 숫자  → 그냥 배열과 같다
mapNum.set(nums[i], i)      // ✅ 키 = 값,     값 = 인덱스
```

반복되는 질문이 **"`target - nums[i]` 라는 *값*이 있나? 있다면 몇 번 인덱스인가?"** 이므로
**값을 키로** 넣어야 `O(1)` 조회가 된다.

### ② 맵을 순회하면 중복이 뭉개진다 — 실제로 4개 케이스가 깨졌다

```ts
for (const [k, v] of mapNum) { ... }    // ❌ 배열이 아니라 맵을 순회
```

**`Map`의 키는 유일하다.**
```ts
mapNum.set(3, 0)      // {3 → 0}
mapNum.set(3, 1)      // {3 → 1}   ← 덮어써짐. 인덱스 0이 사라진다
```

| 입력 | 정답 | 맵 순회 방식 |
|---|---|---|
| `[3,3]` t=6 | `[0,1]` | **undefined** ❌ |
| `[0,4,3,0]` t=0 | `[0,3]` | **undefined** ❌ |
| `[-1,-1]` t=-2 | `[0,1]` | **undefined** ❌ |
| `[1,5,1]` t=2 | `[0,2]` | **undefined** ❌ |

> ### 🔑 `Map`을 만드는 순간 중복 키는 하나로 뭉쳐진다
> **원본 개수만큼 순회해야 한다면, 배열을 순회하고 맵은 조회용으로만 쓴다.**

### ③ 값과 인덱스를 헷갈렸다

```ts
return [i, need]              // ❌ need 는 "필요한 값"이지 인덱스가 아니다
return [seen.get(need), i]    // ✅
```

```
nums = [2,7,11,15] t=9,  i=1 (nums[1]=7),  need = 2
[1, 2] 반환 →  인덱스 2는 nums[2] = 11.   정답은 [0,1]
```

## 최종 정답 — 1패스 해시맵

```ts
function twoSum(nums: number[], target: number): number[] {
    const seen = new Map<number, number>()   // 지금까지 본 값 → 그 인덱스

    for (let i = 0; i < nums.length; i++) {
        const need = target - nums[i]
        if (seen.has(need)) {
            return [seen.get(need)!, i]
        }
        seen.set(nums[i], i)
    }

    return []
}
```

- **시간 `O(n)` / 공간 `O(n)`** — Follow-up 충족
- 검증: 고정 11건(중복·음수·경계값 포함) + 랜덤 30만건 불일치 0. 최대 입력(10⁴ 완주) 2000회 358ms

### 🔑 왜 1패스가 두 문제를 동시에 푸는가

```
i번째에서 조회할 때, seen에는 i보다 앞선 인덱스만 들어 있다
   → 자기 자신과 짝지을 일이 원천적으로 없다      (조건 추가 불필요)
   → 중복 값도 안전하다                            ([3,3] → i=1에서 {3→0} 조회 ✅)
```

**"조회 후 삽입" 순서가 핵심이다.** 삽입을 먼저 하면 자기 자신이 조회에 걸린다.

2패스(맵을 미리 다 만들기)로 하려면 `seen.get(need) !== i` 가드가 **추가로** 필요하고,
그래도 **중복 값 문제는 못 푼다**(맵에 인덱스가 하나만 남으므로).

## 알아야 할 상식

### 1. 공간 ↔ 시간 거래

| | 시간 | 공간 |
|---|---|---|
| 브루트포스 | `O(n²)` = 10⁸ | `O(1)` |
| **해시맵 1패스** | **`O(n)`** | `O(n)` |

**정렬이 있으면** 투 포인터로 `O(n)` / `O(1)` 이 가능하다 → [0167. Two Sum II - Input Array Is Sorted](../../03-Two-Pointers/0167-two-sum-ii-input-array-is-sorted/README.md).
**정렬이 없으면** 공간을 내주는 수밖에 없다. → [해시맵](../../concepts/hashmap.md)

⚠️ **"먼저 정렬하고 투 포인터"는 이 문제에 안 통한다.** 정렬하면 **원래 인덱스가 사라지기** 때문.
(인덱스를 같이 들고 정렬하면 되지만 `O(n log n)` + `O(n)` 이라 해시맵보다 나쁘다)

### 2. 공간이 `O(1)`이 아닌 이유

[0383. Ransom Note](../0383-ransom-note/README.md) · [0242. Valid Anagram](../0242-valid-anagram/README.md) 은 **소문자 26개 고정**이라 `O(1)` 이었다.
여기는 값의 범위가 `-10^9 ~ 10^9` 라 **키 종류가 입력 크기에 비례**한다 → `O(n)`.

> 🔑 기준은 늘 같다 — **"입력이 커지면 이것도 같이 커지나?"** → [시간·공간 복잡도](../../concepts/complexity.md)

### 3. TypeScript — `seen.get(need)` 의 타입

`Map.get()` 은 `number | undefined` 를 반환하므로 `strictNullChecks` 환경에서 `number[]` 반환에 걸린다.
`has` 로 확인한 직후라도 **TS는 그 관계를 추론하지 못한다.**

```ts
return [seen.get(need)!, i]              // non-null 단언
const j = seen.get(need); if (j !== undefined) return [j, i]   // 또는 이렇게
```
→ [0013. Roman to Integer](../../01-Array-String/0013-roman-to-integer/README.md) 에서 정리한 것과 같은 함정

## 실수 노트

- **"target보다 작은 수만 판별"** → 음수가 들어오므로 성립하지 않음. `[10,-5]` t=5 반례 `#Constraints미확인`
- **중첩 루프를 `O(m+n)` 으로 셌다** → 중첩은 곱셈. [0383. Ransom Note](../0383-ransom-note/README.md) 에서 정리한 규칙
- **입력이 하나인데 축을 둘로 나눴다** (`O(m×n)`) → **입력이 하나면 축도 하나, `O(n²)`**
- **맵을 `인덱스 → 값` 으로 만들었다** → 조회하려는 게 "값"이므로 **`값 → 인덱스`** 여야 한다
- **맵을 순회했다** → 중복 키가 뭉개져 `[3,3]` 등 4개 케이스 실패. **배열을 순회하고 맵은 조회용으로**
- **`return [i, need]`** — `need` 는 값이지 인덱스가 아니다
- `let answer = []` 미사용 변수 + `console.log(mapNum)` 방치 `#죽은코드방치` (0125 실수 노트에 같은 지적이 있다)
- ✅ **"반복되는 질문이 뭔가"를 한 번에 답함** — `target - nums[i]` 가 있는지
- ✅ 중첩=곱셈, 맵 방향, 1패스까지 **힌트마다 한 번에 교정**
